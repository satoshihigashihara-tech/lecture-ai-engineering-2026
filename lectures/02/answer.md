# 第2回 解答

## 演習

- この提出は第2回の発展課題の実施結果である。元の架空FAQによる演習結果とは区別する。
- 実行範囲：本人がCodespacesで学習データを生成し、Colabでノートブックを実行した。実装・結果整理・提出文作成にはCodexの支援を使用した。

## 宿題

- 取り組んだレベル：発展
- 変えた設定やデータ：講座の用語集から、Codespacesで `uv run python scripts/make_sft_dataset.py > glossary_sft.jsonl` を実行してQ&Aを116件生成した。ファイルをColabにアップロードし、messages形式を加工せずDataset.from_listに渡してSFTTrainerで学習した。モデルはQwen/Qwen3.5-0.8B、revisionは2fc06364715b967f1860aea9cf38778875588b17。量子化なしのLoRAを使い、r=16、alpha=32、学習率2e-4、20エポック、seed=42、最大系列長512、評価はdo_sample=False・最大出力256トークンとした。学習用とは異なる質問文で、既知語6問、言い換え6問、用語集にない実在語3問の計15問を評価した。testとgoldを用語集に合わせて作り直し、用語名・別名の部分一致で定義を直接返す検索方式とも比較した。
- 結果：300ステップの学習は727.483秒（約12.1分）。学習全体の平均lossは0.372200、最後に記録されたlossは0.068995だった。既知語と言い換えの計12問に対する必須語句一致率は学習前3/12（25.0%）、学習後7/12（58.3%）に上がった。15問の生成評価時間は学習前190.694秒、学習後44.265秒。ただし学習前には長い回答や最大出力長に達したように見える回答が多く、生成時間の差をモデル固有の速度向上とは解釈できない。既知語の概要質問は学習後6/6問で用語集の定義と文字列が完全一致した。一方、言い換えではLoRAを「2ビット」と説明したり、tokenの質問にコンテキストウィンドウの定義を答えたりする誤りが残った。必須語句判定で退行したのはLoRA、token、temperatureの言い換え3問だった。ただし学習前も誤説明を含むため、語句判定の退行と意味上の正誤は同一ではない。
- 検索方式との比較：幻覚の言い換え質問では、検索が「LLM」に一致して別の定義を返した。BERTでも短い別名「r」の部分一致によりLoRAのランクを誤取得した。拡散モデルとグラフニューラルネットワークは見つからないと返した。検索も常に正しいわけではなく、短い別名の一致条件や複数候補の選び方が課題だった。
- 用語集外の質問：学習後のBERT・拡散モデル・グラフニューラルネットワークへの回答は、用語集にない旨を明示せず、用語集の説明を混ぜたような不適切な説明になった。今回の学習では未知語への回答を控える能力は確認できなかった。これらの語は学習データに追加していない。学習前からの一般知識と追加学習の効果を区別する必要がある。
- 回答原文の採点：Codexが用語集の参照定義と原文を照合し、15問すべてに判定と理由を記入した。本人が採点したことを意味しない。既知語と言い換えの12問は「講座の定義に沿って質問に答え、重要な誤説明を含まない」という実行後に明文化した厳格基準で、学習前0/12、学習後6/12、簡易検索11/12となった。学習前には関連する説明が一部あっても誤説明を含むものがあり、この採点は一般的な能力の正解率ではない。temperatureの言い換えは分布の変化に触れる部分的な回答だが、多様性の説明が明確でなく、API指定の説明も混在するため厳格基準では不合格とした。用語集外の3問は一般知識の真偽と分離し、「用語集にないと明示するか」だけを判定した。学習前0/3、学習後0/3、検索2/3だった。ただし非掲載の明示を学習データや評価プロンプトで指示していないため、この数値だけで未知語の識別能力やFT全般の限界を証明したとはいえない。採点基準と各回答の根拠は `advanced/results/manual_review_summary.json` と `manual_review.csv` に保存した。
- 工夫した点：資料指定の学習データを加工せず使い、学習用と評価用の質問文を分離した。評価を既知語・言い換え・用語集外の3種類に分け、同じモデルと生成設定で学習前後を比較した。必須語句の一致率だけでなく、回答原文と検索結果も確認し、誤りの原因を調べた。
- 難しかった点：概要を聞くと定義を正しく再現しても、言い換えで別の概念や誤った説明を返し、全体の数値だけでは理解の程度を判断しにくかった。また、検索でも短い別名による誤検出があり、学習方式と検索方式それぞれの失敗を分けて考える必要があった。
- ファインチューニングが向く場面・向かない場面についての考察：講座に合わせた短い定義や答え方をそろえる用途には効果が見られた。一方、未知語への適切な対応や多様な言い換えへの一般化を保証するものではなかった。定義の更新が多い場合は、再学習を要する方式より用語集を更新する検索方式が扱いやすいが、検索の誤検出対策が必要である。15問・1回ずつの小規模評価で、既知語の定義を学習に含めているため、一般的な性能差や新概念への汎化は断定できない。自然文を学習した実験であり、元のFAQ演習のJSON形式遵守率とは比較していない。

実測原文・設定：`advanced/results/result_colab.json` はColab出力の原本、`result.json` はその測定値と回答原文を保ったまま採点情報を追記したもの。`eval_before.json` と `eval_after.json` は実行時の原本を保持する。採点済みCSVと根拠JSONを併せて提出する。検索比較はPDF資料の「用語集を検索する仕組み」に対応する簡易検索であり、第3回のエージェントをGeminiで実行した結果ではない。
